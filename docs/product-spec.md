# 產品規格：Bussistant 公車幫

> ⚠️ 2026/11/08 更新：目標族群已從「全盲使用者」改為**長者、不熟悉手機的人、新住民**。
> 下面保留當時以視障為主的規格，因為功能優先順序（進站廣播／上車確認／下車提醒）仍然成立，
> 但凡是提到 VoiceOver／全盲的設計前提，以 `CLAUDE.md` 第 1 節為準。

> 子題：用不了。一句話：**讓視障者不用看站牌、不用看車頭，也能自己搭對公車、在對的站下車。**
> 目前範圍是公車，之後延伸到捷運轉乘和步行路段。

## 使用者與情境
- 主要使用者：全盲或低視能、會用 VoiceOver／TalkBack 的人，出門通常戴耳機。
- 痛點：
  1. 看不到站牌上的到站資訊，也看不到進站公車的號碼。
  2. 很多車同時進站時，不知道哪一台才是要搭的，常需要攔車問司機。
  3. 上車後不確定自己有沒有上對車。
  4. 不確定什麼時候該按鈴下車。
- 情境：出門 → 走到公車站 → 等車 → 上車 → 坐車 → 下車 → 轉乘或步行到目的地。

## 功能（依優先順序）

### P0-1 進站廣播
- 用 App 的 `location` 取得位置，找最近的公車站牌（TDX `Bus/Station`），讓使用者選路線與方向。常用路線可以存成捷徑。
- 輪詢 TDX N1（`Bus/EstimatedTimeOfArrival`），用語音播報，例如「307 往板橋，還有 3 分鐘，這班是低地板」。
- 進站時用 A2（`Bus/RealTimeNearStop`）偵測「該路線、該方向的車到了這一站」，加強提示（語音 + 震動）：「307 進站了」。
- 低地板判斷：A2 的 `PlateNumb` join `Bus/Vehicle` 的 `IsLowFloor`。
- 同一站牌兩個方向可能是不同 StopUID，方向一定要分清楚。

### P0-2 上車確認（GPS 軌跡比對）
- 上車後，持續比對「使用者手機 GPS」與「目標車輛的即時位置」。目標車輛是進站時記下的車牌，即時位置來自 TDX A1 `Bus/RealTimeByFrequency`。
- 連續 N 次（例如 3 次）距離小於門檻（例如 50 m），且使用者在移動中 → 確認：「確認你在 307 上」。
- 如果軌跡吻合的是**別台**車／別條路線 → 警告：「你可能搭到 2XX，下一站是 XX，可以在這站下車」。
- 限制：A1 約每 15–60 秒更新一次，確認會有約 1 分鐘的延遲；同站同時發車時需要多筆資料才分得出來。Demo 時要誠實說明。
- 延伸（先不做）：鏡頭辨識車頭路線號碼（裝置端 OCR，要確認套件授權）；與公運處合作做「預約上車通知司機」。

### P0-3 下車提醒
- 用 TDX `Bus/StopOfRoute` 拿站序，加上使用者 GPS／車輛 A2 位置，算出剩幾站。
- 提前播報：「再 2 站到 XX」、「下一站 XX，請準備按鈴」，並震動。

### P1 轉乘對接
- 下車後如果要轉捷運，用 TDX Metro `StationExit`（`Elevator`）和 data.taipei 捷運無障礙電梯座標，選有電梯的出口；電梯維修或異常時提醒。

### P1 步行路段提醒
- 用資料提醒，不用鏡頭：路線附近有施工就提醒（施工資料集要在四個平台上確認名稱）；天氣只能用四個平台上有的資料（例如城市儀表板的氣象元件）。
- 鏡頭即時障礙偵測（裝置端模型）是延伸題目，先不做。

## 設計原則（視障 = 語音優先）
- 主畫面只有一顆超大按鈕＋一行狀態文字；所有狀態都要能被朗讀。
- 狀態更新用 `aria-live` 區塊，讓使用者自己的螢幕閱讀器用他習慣的語速唸；需要主動提醒（進站、下車）時再用 App 端 TTS 和震動。
- 不靠顏色、不靠位置傳達資訊；按鈕都要有清楚的 label。
- 行程進行中要保持螢幕不關（App 端 wakelock），否則 WebView 的 JS 會被暫停、廣播會斷。

## 技術需求
- App 自訂 Handler：`tts_speak`（系統 TTS，例如 `flutter_tts`）、`vibrate`、`wakelock`（例如 `wakelock_plus`）。採用前確認授權，並確認離線可用。
- 後端：代理 TDX，金鑰不能放前端；統一快取 N1／A1／A2 結果，避免每台手機各自打爆 TDX 的流量限制。
- 前端：Mock 模式（沒有 `flutterObject`、或開啟「模擬行程」時用假資料）。

## Demo 計畫（重要）
現場在天母，沒辦法真的帶評審上公車。
1. **真實**：在會場最近的站牌查即時到站，現場播報 → 證明串接的是真資料。
2. **模擬行程**：今天先錄一段真實的 A1／A2 資料和一段 GPS 軌跡，Demo 時回放：進站 → 上車確認（含「搭錯車」警告）→ 下車提醒。介面上要標示「模擬行程」，並如實說明。
3. 全程用 VoiceOver／TalkBack 操作，並戴耳機或外放給評審聽。
